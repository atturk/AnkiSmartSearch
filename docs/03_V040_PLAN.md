# Piano v0.4.0 — recall, robustezza Stage 1, sicurezza della collezione

Origine: code review e test del 2026-11-09 su lezioni reali (RT, Patologia Generale 2) e sul profilo Anki "Test".
Misure chiave: il modello estrae in mediana 5 concetti (il tetto 12 non è mai raggiunto); `top_k_per_concept=8`
esclude carte centrali (es. ITP, HIT); 3 chiamate Stage 1 su 24 falliscono per escape LaTeX (`$\beta$` → `\b`
invalido nel JSON) e il fallback silenzioso produce 0 carte; Stage 1 ≈ 52-84 s/unità con Gemma.

## Regole per chi implementa

- Lavora SOLO dentro questa repo, sul branch `agy/v0.4.0`. Non toccare file fuori dalla repo (niente `~/.local/bin`,
  niente Python di sistema/Homebrew, niente profili o cartelle di Anki, niente `pip install` globali).
- Una voce = un commit, messaggio `N. <titolo della voce>`. Non fare push, non aprire PR.
- Dopo ogni voce: `python3 -m pytest -q tests` deve passare. Aggiungi test per ogni comportamento nuovo
  (i test esistenti usano un MockAnkiCol in `tests/test_storage_and_search.py`).
- Codice e commenti in inglese come il resto della repo; stringhe UI in italiano.
- Mantieni la compatibilità con config e database esistenti (migrazioni leggere come quelle già in `storage.py`).
- Nessuna dipendenza nuova: Anki non include numpy né altre librerie; solo standard library.

## Voci

### 1. Stage 1 robusto (ai_client.py, search_pipeline.py)
- Prima di inviare il testo, normalizza il LaTeX inline: `$\beta$`→`β`, `$\kappa$`→`κ`, `$\alpha$`→`α` ecc. (mappa delle
  lettere greche + rimozione dei `$` e dei comandi residui `\mathrm{}` ecc.). Funzione pura in `text_utils.py`.
- In `extract_clean_json`: se `json.loads` fallisce, ripara gli escape non validi (backslash non seguito da
  `"\/bfnrtu`) raddoppiandoli e riprova, prima dei tentativi esistenti.
- `chat_completion_json`: parametro opzionale `json_schema`; se fornito invia
  `response_format={"type":"json_schema","json_schema":{...}}`. Se il server risponde 400 per response_format,
  riprova una volta senza. Aggiungi `max_tokens` configurabile (default 4096).
- `/no_think` solo se il nome del modello contiene `qwen`.
- Se il parsing fallisce: un secondo tentativo; se fallisce ancora NIENTE fallback a parole ASCII. L'unità va
  marcata con errore (`unit_error`) e mostrata come tale nel riepilogo e nella cronologia; nessuna carta viene
  riattivata per quell'unità.

### 2. Prompt Stage 1: un concetto per entità, ancorato al testo
- Togli "3 to 12". Chiedi un concetto per ogni malattia, meccanismo, molecola, farmaco, segno o criterio numerico
  citato; vieta di accorpare entità diverse e i concetti generici senza un'entità specifica; ignora divagazioni
  non mediche (costi, organizzazione, aneddoti).
- Nuovo campo `quote_it`: la frase (o parte di frase) del testo da cui nasce il concetto. Salvalo in
  `ExtractedConcept` e in `ConceptCoverage` (e nel JSON della cronologia).
- Usa lo schema JSON della voce 1 con tutti i campi required.

### 3. Selezione per concetto con taglio relativo (search_pipeline.py, config_manager.py, config.json)
- Sostituisci il top-k fisso: per ogni concetto tieni le note con
  `score >= max(min_threshold, best_score - relative_score_window)`, fino a `max_notes_per_concept`.
- Nuove chiavi: `relative_score_window` (default 0.08), `max_notes_per_concept` (default 30).
  `max_cards_per_unit` default 150. Migrazione: se esiste solo `top_k_per_concept`, ignoralo ma non rompere.
- Mantieni la logica che non fa rubare posti alle note già attive.
- Aggiorna lo slider/campi delle impostazioni se mostrano top_k.

### 4. Ricerca lessicale pulita (storage.py `search_fts`)
- Scarta token < 3 caratteri e stopword (inglese + italiano, lista breve nel codice).
- Keyword multi-parola → query a frase (`"acute pancreatitis"`) in OR con i singoli token significativi.
- Filtra i candidati dentro la query SQL (o alza il LIMIT) invece di tagliare a 300 sull'intera collezione.
- Non usare `keywords_it` nella FTS quando il mazzo è inglese (opzione `fts_use_italian_keywords`, default false).

### 5. Istruzione per le query degli embedding
- Opzione `embed_query_instruction` (default vuota); se il modello di embedding contiene `qwen3-embedding` e
  l'opzione è vuota, usa `Instruct: Given a medical lecture concept, retrieve flashcards that test it\nQuery: `.
  Applicala SOLO alle query (Stage 2), mai alle note indicizzate.

### 6. Verifica Stage 3 corretta
- Passa il testo intero dell'unità (non `[:1200]`) e, per ogni candidata, il `quote_it` del concetto che l'ha trovata.
- Se il modello risponde con lista vuota valida, nessuna candidata passa (oggi le tiene tutte). Solo un errore di
  chiamata conserva il batch.
- Resta disattivata di default.

### 7. Modifiche alla collezione sul thread principale (ui/worker.py, deck_ops.py, ui/main_dialog.py)
- Il worker in background fa solo parsing, indicizzazione e ricerca e restituisce i risultati.
- Unsuspend, creazione/ricostruzione dei mazzi filtrati e rollback vanno eseguiti sul thread principale con
  `aqt.operations.CollectionOp` (o `mw.taskman.run_on_main` + `mw.col` con `undo` dove possibile), con un
  punto di Annulla di Anki chiamato "Smart Search".
- Le letture della collezione nel worker (find_notes, query sulle carte) vanno fatte prima di avviarlo, sul main
  thread, o con `QueryOp`.
- Mantieni `execute_unit_deck_creation` e `rollback_run` testabili con MockAnkiCol.
- Mantieni i segnali `progress_sig`, `finished_sig`, `error_sig` di `SearchBatchWorker` e `RollbackWorker` e il
  formato del dict finale (`status`, `units_processed`, `results` con oggetti RunResult): li usa un harness di test.

### 8. Rollback corretto (deck_ops.py)
- Con "mantieni ripassate" una carta è ripassata solo se ha voci in `revlog` con `id >= created_at*1000`; togli
  il criterio `reps > 0`.
- Non riusare un mazzo filtrato che appartiene a un altro run non annullato: se il nome esiste ed è di un run
  attivo, crea un nome nuovo con suffisso orario.

### 9. Batch con carte in comune (ui/worker.py, deck_ops.py)
- Calcola prima i risultati di tutte le unità, poi assegna ogni nota all'unità dove ha il punteggio più alto;
  le altre unità la elencano come "condivisa con <unità>" nella copertura. Solo dopo riattiva e crea i mazzi.

### 10. Cronologia per profilo (storage.py, ui/main_dialog.py)
- Aggiungi a `run_history` la colonna `profile` (nome profilo `mw.pm.name`, migrazione con default '').
- La cronologia mostra solo i run del profilo aperto; il rollback di un run di un altro profilo è rifiutato.
  Run vecchi con profile '' visibili ma con avviso.

### 11. Riepilogo e copertura onesti (ui/main_dialog.py)
- Riepilogo: unità con errore Stage 1 in evidenza, con il messaggio.
- Copertura: "coperto" / "parziale" / "scoperto" conteggiati separatamente; la percentuale conta solo i coperti.
- Nella finestra di dettaglio mostra `quote_it` accanto a ogni concetto.
